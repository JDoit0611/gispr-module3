def sedf_to_gdf(sdf):
    """Spatially Enabled DataFrame -> GeoDataFrame. Works whether or not your arcgis
    version has sdf.spatial.to_geodataframe()."""
    import geopandas as gpd
    if hasattr(sdf.spatial, "to_geodataframe"):
        return fiona_safe(sdf.spatial.to_geodataframe())
    geom_col = getattr(sdf.spatial, "name", None) or "SHAPE"
    sr = sdf.spatial.sr
    epsg = sr.get("latestWkid") or sr.get("wkid")
    geoms = gpd.GeoSeries.from_wkt(sdf[geom_col].apply(lambda g: None if g is None else g.WKT), crs=epsg)
    return fiona_safe(gpd.GeoDataFrame(sdf.drop(columns=geom_col), geometry=geoms))

def list_layers(path):
    """Layer names in a GeoPackage/GDB — works with or without pyogrio installed."""
    import pandas as pd, geopandas as gpd
    try:
        return gpd.list_layers(path)            # needs pyogrio
    except ImportError:
        import fiona                            # ships with the ArcGIS Pro / older geopandas envs
        return pd.DataFrame({"name": fiona.listlayers(str(path))})

def fiona_safe(gdf):
    """Plain numpy dtypes for writing with the fiona engine (it can't handle pandas
    nullable dtypes like Float64/Int64/string, which ArcGIS SeDFs use). pyogrio doesn't need this."""
    import pandas as pd
    out = gdf.copy()
    geom = out.geometry.name
    for col in out.columns:
        dt = out[col].dtype
        if col == geom or not isinstance(dt, pd.api.extensions.ExtensionDtype) or isinstance(dt, pd.DatetimeTZDtype):
            continue
        if pd.api.types.is_float_dtype(dt) or (pd.api.types.is_integer_dtype(dt) and out[col].isna().any()):
            out[col] = out[col].astype("float64")
        elif pd.api.types.is_integer_dtype(dt):
            out[col] = out[col].astype("int64")
        else:                                   # string, boolean, categorical, ...
            out[col] = out[col].map(lambda v: None if pd.isna(v) else str(v)).astype(object)
    return out

Section 3 — CRS Check and Reprojection¶

CRS errors are the #1 source of silent failures in spatial analysis. A layer that plots in the wrong place, measurements in degrees instead of meters, or an overlay that's thousands of kilometers off — all CRS problems.

The four CRS questions to ask every time you load data¶

  1. What CRS is it? — gdf.crs / st_crs(sf_obj)
  2. Is it geographic or projected? — degrees (geographic) vs. meters/feet (projected)
  3. Does it match my other layers? — they must share a CRS before any spatial operation
  4. Is it appropriate for my analysis? — distance/area measurements require a projected CRS in appropriate units

Common EPSG codes for Pacific Northwest work¶

EPSG Name Type Units Use case
4326 WGS 84 Geographic Degrees GPS, web data, GeoJSON
3857 Web Mercator Projected Meters Web tile basemaps (not for measurement)
2926 WA State Plane North (ft), NAD83(HARN) Projected US survey feet Course standard — Puget Sound county/state agency data
2927 WA State Plane South (ft) Projected US survey feet Southern WA state/county data
32610 UTM Zone 10N (WGS 84) Projected Meters Federal/regional data, metric analysis
4269 NAD 83 Geographic Degrees USGS and federal data

⚠️ The set_crs vs. to_crs trap — a silent CRS bug¶

This is the single most common error in this module. Confusing these two functions produces geometry that looks fine on a map but is silently wrong for every spatial operation.

  • set_crs() / st_set_crs() = "I'm declaring what the CRS already is." Use only when the CRS is missing or mislabeled in the metadata. Does not move coordinates.
  • to_crs() / st_transform() = "Convert the coordinates to a new CRS." Use to align layers before any spatial operation. Moves coordinates.

Mnemonic: set_crs = slap a label. to_crs / st_transform = transform the numbers. When in doubt: check the CRS, then transform.

Section 4 — Clean and Standardize Attribute Tables¶

Run this sequence on every new dataset before any spatial operation:

Standardize column names — lowercase, strip whitespace, replace spaces/punctuation Fix data types — coerce numeric and date columns; let unparseable values become null rather than crashing Drop rows missing a key join field — and report how many rows you kept errors='coerce' in pandas and as.numeric() / as.Date() in R both turn unparseable values into NA rather than raising an error — this lets the pipeline continue, so you can inspect what failed afterward instead of debugging a crash mid-script.

Section 5 — Tabular → Spatial¶

Any CSV with coordinate columns can become a spatial dataset in three lines of code. The critical detail: longitude is X (first argument), latitude is Y (second argument) — swap them and your points land in the ocean, or worse, somewhere that still looks plausible until someone checks the map.

⚠️ Watch for lon/lat swap points_from_xy(x=LON, y=LAT) in Python and coords = c("longitude", "latitude") in R both expect longitude first. Get the order backwards and you'll generate points in the wrong hemisphere — sometimes in the ocean, which is at least obviously wrong; sometimes just shifted, which is much harder to catch without a plot.

The plot check is mandatory, not optional. It catches a swapped lon/lat in about two seconds — far faster than debugging a downstream spatial join that silently returns zero matches.

# [Python] Lab Step 3 — Clean Attributes
import re

def clean_columns(df):
    """lowercase, strip, spaces→underscores, drop punctuation — leaves the geometry column alone"""
    geom = df.geometry.name if isinstance(df, gpd.GeoDataFrame) else None
    std = lambda c: re.sub(r"[^a-z0-9_]", "", c.lower().strip().replace(" ", "_"))
    return df.rename(columns={c: std(c) for c in df.columns if c != geom})

obs = clean_columns(obs_raw)
print("Standardized columns:", list(obs.columns))

# Fix data types — unparseable values become NaN/NaT, not a crash

obs["survey_date"] = pd.to_datetime(obs["survey_date"], format="mixed", errors="coerce")
obs["species"] = obs["species"].str.strip().str.title()          # ' coho ' → 'Coho'
print("Species values:", sorted(obs["species"].unique()))
print("Unparseable counts →", obs["count"].isna().sum(), "NaN (kept, but flagged)")

# Drop rows missing the key field (obs_id)
obs_clean = obs.dropna(subset=["obs_id"]).copy()
print(f"\n{len(obs_clean)}/{len(obs)} rows kept after dropping nulls in obs_id")

  1. I would reach for SeDF when the data lives in an Esri based platform, as well as if I had access to an ArcGIS license. Alternatively i would use GeoPandas for any file based data.   2. set_crs only labels the data with a CRS so the coordinates dont change. I used this after building points from the field CSV long and lat. columns since those values were already in EPSG:4326. to_crs on teh other hand transforms the coordinates to whatever you want. I used it to convertevery layer to EPSG:2926 so they could be spatialy joined correctly.

    1. read_csv: load the table, then check the row count and that no lat/lon values are missing.

    4. to_crs(epsg=2926): reproject to the course CRS and check that the bounds became large foot values.
    5. to_file(..., driver="GPKG"): save the layer, then read it back to confirm the feature count and layers before opening it in ArcGIS Pro.
